ПРИЛОЖЕНИЕ А. Модуль динамического построения дерева категорий (специальностей)
Скопируйте блок ниже в онлайн-редактор блок-схем (режим «текст» / «алгоритм»).
================================================================================

АЛГОРИТМ ПостроениеДереваСпециальностей

НАЧАЛО

Выполнить HTTP GET запрос к адресу /api/specialties/tree

ЕСЛИ ответ сервера имеет код ошибки ТО
    Вывести сообщение «Не удалось загрузить дерево специальностей»
    ПЕРЕХОД К КОНЕЦ
КОНЕЦ ЕСЛИ

Прочитать из ответа JSON-массив nodes и массив tree

Создать пустой контейнер specialty-tree на странице

ЕСЛИ массив tree пустой ТО
    Скрыть контейнер specialty-tree
    Показать резервную сетку specialty-grid
    ПЕРЕХОД К КОНЕЦ
КОНЕЦ ЕСЛИ

Для каждого узла root из tree (корневые узлы, parentId = null)

    Создать элемент списка LI для специальности root

    Создать кнопку BUTTON с атрибутом data-specialty = root.id

    Записать в кнопку код специальности root.code и название root.name

    ЕСЛИ специальность недоступна для выбора (не ПД) ТО
        Установить кнопке признак disabled
    КОНЕЦ ЕСЛИ

    ЕСЛИ у узла root есть дочерние узлы children ТО
        Вызвать рекурсивную процедуру ОтрисовкаУровня(children, глубина + 1)
        Вложить полученный подсписок UL внутрь LI
    КОНЕЦ ЕСЛИ

    Добавить LI в контейнер specialty-tree

КОНЕЦ ЦИКЛА

Показать контейнер specialty-tree
Скрыть резервную сетку specialty-grid

КОНЕЦ


--------------------------------------------------------------------------------
Процедура ОтрисовкаУровня(списокУзлов, глубина)

НАЧАЛО процедуры

Создать вложенный список UL с отступом по глубине

Для каждого узла node из списокУзлов

    Создать LI и кнопку BUTTON (data-specialty = node.id)

    ЕСЛИ у node есть children и children не пустой ТО
        Вызвать ОтрисовкаУровня(node.children, глубина + 1)
        Вложить подсписок в LI
    КОНЕЦ ЕСЛИ

    Добавить LI в UL

КОНЕЦ ЦИКЛА

Вернуть UL

КОНЕЦ процедуры

    ПЕРЕХОД К КОНЕЦ

Сохранить specialtyId как активную специальность

Выполнить HTTP GET /api/equipment?specialtyId={specialtyId}

ЕСЛИ ответ сервера имеет код ошибки ТО
    Вывести в списке оборудования сообщение об ошибке
    ПЕРЕХОД К КОНЕЦ
КОНЕЦ ЕСЛИ

Прочитать JSON-массив items (карточки оборудования)

Очистить контейнер equipment-list от предыдущих карточек

Установить заголовок, тип, описание и список особенностей в правой панели

Обновить метку специальности и счётчик «N объектов»

Прокрутить страницу к разделу «Оборудование и 3D модель»

ПРИЛОЖЕНИЕ В. Модуль добавления учебного экспоната и генерации QR-кода
================================================================================

АЛГОРИТМ ДобавлениеЭкспонатаИГенерацияQR

НАЧАЛО

Ожидать нажатие кнопки «Добавить модель и сгенерировать QR» в админ-панели

Проверить наличие токена авторизации администратора

ЕСЛИ токен отсутствует ТО
    Вывести «Требуется авторизация»
    ПЕРЕХОД К КОНЕЦ
КОНЕЦ ЕСЛИ

Считать из формы: specialtyId, title, type, short, description, features, modelUrl, файл glb

ЕСЛИ не заполнены specialtyId, title, type, short, description ТО
    Вывести «Заполните обязательные поля»
    ПЕРЕХОД К КОНЕЦ
КОНЕЦ ЕСЛИ

ЕСЛИ не указан modelUrl И файл glb не выбран ТО
    Вывести «Укажите URL GLB или загрузите файл»
    ПЕРЕХОД К КОНЕЦ
КОНЕЦ ЕСЛИ

Сформировать multipart/form-data и отправить POST /api/admin/equipment

--- Обработка на сервере ---

ЕСЛИ пароль/токен администратора неверный ТО
    Вернуть код 401
    ПЕРЕХОД К КОНЕЦ
КОНЕЦ ЕСЛИ

ЕСЛИ валидация полей не пройдена ТО
    Вернуть код 400
    ПЕРЕХОД К КОНЕЦ
КОНЕЦ ЕСЛИ

НАЧАЛО ТРАНЗАКЦИИ SQLite (BEGIN)

ЕСЛИ загружен файл glb ТО
    Сохранить файл в каталог public/models
    Вычислить modelFileSize = размер файла в байтах
    Вычислить modelFileHash = SHA-256(содержимое файла)
    modelPath = "/models/" + имя_файла
ИНАЧЕ
    modelPath = modelUrl из формы
    modelFileSize = пусто
    modelFileHash = пусто
КОНЕЦ ЕСЛИ

Сформировать уникальный equipmentId на основе title

Выполнить INSERT INTO equipment
    (id, specialty_id, title, type, short, description,
     features_json, model, environment, variant, hotspots_json,
     sort_order, model_file_size, model_file_hash)

ПОДТВЕРДИТЬ ТРАНЗАКЦИЮ (COMMIT)

Сформировать URL просмотра: /view.html?id={equipmentId}&scan=1

Вызвать библиотеку qrcode: сгенерировать изображение QR по URL

Вернуть клиенту id, title, url

--- Конец обработки на сервере ---

ЕСЛИ ответ сервера успешен ТО
    Отобразить QR-код в модальном окне
    Вывести подпись «Отсканируйте для просмотра на телефоне»
    Обновить каталог объектов в админ-панели
ИНАЧЕ
    Вывести текст ошибки из ответа
КОНЕЦ ЕСЛИ

ПРИЛОЖЕНИЕ Д. Модуль логирования сканирований стендовых QR-кодов
================================================================================

АЛГОРИТМ ЛогированиеСканированияQR

НАЧАЛО

Получить GET-запрос на /catalog/{equipmentId}
    или GET /view.html?id={equipmentId}&scan=1

Проверить корректность equipmentId (латиница, цифры, дефис)

ЕСЛИ equipmentId некорректен ТО
    Вернуть код 400
    ПЕРЕХОД К КОНЕЦ
КОНЕЦ ЕСЛИ

Выполнить SELECT из equipment WHERE id = equipmentId

ЕСЛИ запись не найдена ТО
    Вернуть код 404
    ПЕРЕХОД К КОНЕЦ
КОНЕЦ ЕСЛИ

Считать viewedAt = текущие дата и время (ISO)
Считать ip = req.ip
Считать userAgent = заголовок User-Agent запроса
Считать route = URL запроса

Выполнить INSERT INTO scan_logs
    (equipment_id, viewed_at, ip, user_agent, route)

Дополнительно дописать строку JSON в файл logs/scan.log (резервный журнал)

ЕСЛИ запрос пришёл на /catalog/{id} ТО
    Выполнить перенаправление 302 на /view.html?id={id}&scan=1
ИНАЧЕ
    Отдать HTML-страницу view.html клиенту
КОНЕЦ ЕСЛИ

Клиент загружает GLB в полноэкранный model-viewer

КОНЕЦ
(операция логирования не блокирует отображение 3D-модели)

================================================================================

АЛГОРИТМ КаскадноеУдалениеЭкспоната

НАЧАЛО

Ожидать нажатие кнопки «Удалить» в админ-панели

Показать диалог подтверждения «Удалить объект из базы?»

ЕСЛИ пользователь отменил удаление ТО
    ПЕРЕХОД К КОНЕЦ
КОНЕЦ ЕСЛИ

Отправить DELETE /api/admin/equipment/{equipmentId}

--- Обработка на сервере ---

Проверить авторизацию администратора

ЕСЛИ не авторизован ТО
    Вернуть 401
    ПЕРЕХОД К КОНЕЦ
КОНЕЦ ЕСЛИ

Выполнить SELECT model FROM equipment WHERE id = equipmentId

ЕСЛИ запись не найдена ТО
    Вернуть 404
    ПЕРЕХОД К КОНЕЦ
КОНЕЦ ЕСЛИ

Выполнить DELETE FROM equipment WHERE id = equipmentId

(СУБД SQLite по правилу ON DELETE CASCADE
 автоматически удаляет строки из scan_logs для этого equipment_id)

ЕСЛИ model начинается с "/models/" ТО
    Удалить файл GLB с диска сервера
КОНЕЦ ЕСЛИ

Вернуть клиенту { id, deleted: true }

--- Конец обработки на сервере ---

ЕСЛИ удаление успешно ТО
    Убрать карточку из списка админ-каталога
    Вывести «Объект удалён»
    Установить флаг обновления каталога на главной странице
ИНАЧЕ
    Вывести сообщение об ошибке
КОНЕЦ ЕСЛИ
